# 📑 开发指导文档：本地优先的异步 AI 智能体流水线

## 🎯 核心架构原则：输入零延迟，后台自流转

* **本地优先（Local-First）**：所有碎片化输入**必须在 10 毫秒内写入本地数据库**，并立即释放 UI 界面，用户无需等待任何网络或 AI 响应。
* **异步流转（Async Agentic Flow）**：建立本地任务队列。AI 意图识别、向量查重、大类表格分发全部在后台异步执行。网络好时秒级完成，网络差时静默挂起、等待恢复后自动处理。

---

## 🧭 一、 数据库状态机扩展（基于现有数据库）

在现有的笔记数据表中，必须引入 `processing_status`（处理状态）字段，用以驱动后台流水线：

| 状态值 (`String/Enum`) | 触发时机 | 对应后台动作 |
| --- | --- | --- |
| **`synced_local` (就绪态)** | 用户点击发送，数据**刚写入本地** | UI 立即放行；触发后台异步队列。 |
| **`vector_checking` (查重中)** | 后台启动，正在调取本地/云端向量库 | 对比历史相似话题，判断是否需要合并。 |
| **`ai_routing` (路由中)** | 查重通过，正在进行大模型 Function Calling | 抽取实体（时间、金额、人名），识别大类。 |
| **`dispatched` (完结态)** | 数据已成功分发至 CRM/财务/待办等大类表 | 在信息流中渲染对应的双向链接标签。 |
| **`failed_retry` (挂起态)** | 网络断开或大模型超时 | 暂停处理，开启网络状态监听，等网好时自动重试。 |

---

## 🛠️ 二、 四大核心后台处理流水线（异步流转逻辑）

### 1. 拦截与查重流（本地向量闭环）

* **动作**：新文本入库后，后台异步计算其 Vector Embedding。
* **网络断卡点**：若使用云端 Embedding 模型且网络不通，**自动跳过此步**，不影响后续本地粗糙分类，或挂起等待。
* **业务逻辑**：检索到语义相似度 $> 85\%$ 的历史记录，触发系统通知或在内容页顶部生成轻提示：*“检测到相似话题【碳化硅陶瓷膜参数】，是否合并？”*

### 2. 大脑路由与实体抽取流（双模态自动控制）

* **智能降级**：
* **网络良好**：调用云端高级大模型进行精准的 `Function Calling`，输出结构化 JSON。
* **网络离线**：切换为**本地正则/关键词弱路由匹配**（例如：检测到“￥”或“款”自动归为财务预备态；检测到时间自动归为待办预备态），确保离线时也能完成基础归类。



### 3. 结构化降维分发流（双向链接织造）

* **动作**：解析第二步产出的 JSON，异步写入对应的业务表（如：CRM客户表、合同表、财务记账表、待办日程表）。
* **织造**：在主闪念笔记与衍生出的表格数据间建立 `UUID` 双向绑定。使用户在内容页能看到数据流向，在表格页能追溯原始闪念。

### 4. 废话衰减与生命周期管理

* **废话判定**：经 AI 路由或用户手动标记为 `日常废话` 的内容，进入衰减时钟。
* **视觉淡出**：主信息流根据 `创建时间 - 当前时间` 的半衰期算法，逐渐降低该条目的透明度（Alpha 值），或在超过 48 小时后自动折叠进“流水碎碎念”归档区。

---

## 🚨 三、 异常隔离与弹性体验 (Fault Tolerance)

* **静默重试机制**：AI 模块调用设置 15 秒超时限制。超时或报错后，数据状态变更为 `failed_retry`。系统注册 `Connectivity` 监听，当检测到 Wi-Fi/蜂窝网络恢复时，**静默唤醒后台 Service 重新洗牌流转**。
* **非阻断式 UI 提示**：在主列表和内容页的卡片角落，用微小的图标（如：🔄 正在同步 / ⏳ 等待网络 / ✅ 已结构化）展示流转进度，允许用户在同步进行时继续追记或编辑。

---

有了这套“本地写前日志 + 异步状态机”的流水线规范，AI 在帮你写后台代码时就会非常明确地去用多线程或后台隔离区（Isolate）来处理数据，绝不会卡死你的前端界面。
