# Locus 架构设计蓝图：数据同步与双引擎搜索

## 一、核心数据底座：PocketBase + SQLCipher + Zvec 本地三引擎

这是整个系统的基石，负责保障数据的绝对安全、多端一致性以及离线的 AI 能力。

- **本地结构化缓存（Flutter + SQLCipher）**：作为离线可用和极速读取的缓存。所有笔记的结构化元数据（标题、标签、时间、软删除状态等）均保存在本地，确保断网状态下应用依然流畅。
- **本地 AI 检索引擎（Zvec）**：作为嵌入在 Flutter 应用进程内的"超级记忆芯片"。
    - **零运维与隐私**：无需部署独立服务器，数据完全留在本地设备。支持 WAL 预写日志，断电不丢数据。
    - **混合检索**：利用 Zvec 的 `MultiQuery` 接口，同时支持向量语义检索（找"意思相近"的内容）和原生全文检索 FTS（找"特定关键词/错误码/人名"），通过 RRF（倒数排名融合）算法在本地瞬间完成混合召回。
- **权威主数据源（PocketBase）**：作为多端同步的"真理之源（Single Source of Truth）"。部署在局域网主机或云服务器上，提供 REST API 和实时订阅。
- **LWW 增量同步协议**：
    - **数据模型**：所有表必须包含全局唯一 `id` (UUID)、`updated_at` (毫秒级时间戳) 和 `is_deleted` (软删除标记)。
    - **同步逻辑**：采用"手动触发"或"后台静默"的 Push-Pull 模型。通过比对 `last_sync_timestamp`，仅上传/下载增量数据。遇到并发修改时，严格遵循 LWW（Last Write Wins，时间戳较新者覆盖）策略，从应用层彻底杜绝文件级冲突。

## 二、AI 搜索双引擎：Zvec 本地混合检索 + 结构化查询

针对 AI 无法精准理解结构化数据的痛点，采用"本地双引擎 + 云端精准查询"的并行架构：

- **本地混合检索引擎（Zvec）**：专门负责处理 MD 文档和笔记正文的"模糊语义检索"与"关键词检索"。
    - **切分与注入**：将长文本按语义切分为 200-500 Token 的 Chunk，调用本地或云端 Embedding 模型向量化后存入 Zvec。同时，必须将 `note_id` 作为 Metadata 绑定到向量上。
    - **FTS 补充**：在 Zvec 中为 `content` 字段建立全文索引，弥补纯向量检索在精确匹配（如特定函数名、专有名词）上的不足。
- **结构化查询（Text-to-SQL）**：专门处理订单、客户、金额等精确查询。
    - **Schema 注入**：将 PocketBase 的表结构（表名、字段名、字段类型）以 JSON 或文本形式作为 System Prompt 喂给大模型。
    - **安全执行**：AI 仅负责生成 `SELECT` 语句，后端拦截该 SQL 并在 PocketBase 中执行，将返回的 JSON 结果注入到 AI 的上下文中。

## 三、核心大脑：AI Router（智能路由）

在用户提问与大模型生成之间，增加一个轻量级的"意图识别层"：

1. **意图分类**：利用轻量级模型或 Prompt 工程，判断用户问题是属于"语义类"（如："总结XX项目会议纪要"）、"结构类"（如："查一下张三的订单总额"）还是"混合类"。
2. **分发执行**：
    - **语义/关键词类** → 优先在本地调用 Zvec `MultiQuery`，毫秒级召回 Top-K 相关文本片段（全程离线可用）。
    - **结构类** → 触发 Text-to-SQL，生成并执行 SQL，返回精确数据。
    - **混合类** → 并发执行上述两步，将结果合并。
3. **上下文拼接**：将 Zvec 召回的文本片段和 SQL 查询结果统一格式化，作为背景知识（Context）注入给最终的大语言模型（LLM）生成回答。

## 四、内容溯源（Grounding）与 UI 展现

为了让 AI 的回答可信且可验证，必须在工程上实现严格的引用绑定：

- **文本溯源**：要求 LLM 在回答中引用文本时，必须以特定格式（如 `[ref_note_id]`）标注。Flutter 前端通过正则解析这些标记，将其渲染为可点击的超链接或角标，点击后直接跳转至对应的 Obsidian 笔记或 Flutter 详情页。
- **结构化溯源**：对于 AI 回答中涉及的订单、金额等结构化数据，前端直接渲染为"数据卡片（Data Card）"。卡片展示核心字段，并附带"查看原始数据"按钮，点击后通过 DeepLink 跳转至 PocketBase 后台对应的记录详情。

## 五、落地实施路线图（Roadmap）

- **Phase 1：夯实底座（当前）**
完成 PocketBase 部署与 Flutter 端的 SQLCipher 集成。跑通基于 LWW 策略的手动增量同步（Push/Pull），确保多端数据绝对一致。
- **Phase 2：本地 AI 引擎接入（Zvec 落地）**
在 Flutter 端集成 Zvec SDK。设计 ETL 流程：当 PocketBase 数据同步到本地 SQLCipher 后，触发后台任务，将新增/修改的文本向量化并写入 Zvec，同时建立 FTS 索引。
- **Phase 3：AI 路由与混合检索接入**
开发 AI Router 模块。实现 Text-to-SQL 的 Prompt 调优与 SQL 安全校验机制。打通 Zvec 本地混合检索与 SQL 查询的结果合并逻辑。
- **Phase 4：溯源与前端体验优化**
在 Flutter 端实现文本角标解析与数据卡片渲染，完成从"AI 回答"到"原始数据"的闭环跳转。

---

这套架构将强大的 AI 检索能力完全下沉到了本地设备，既保证了 SQLCipher 级别的隐私与安全，又利用 Zvec 实现了零延迟的离线语义搜索，是目前独立开发者构建下一代 AI 笔记应用的最优解。
