# AI 收件箱按意图细化布局计划

## 概述

本次是在上一轮 AI 收件箱卡片重构基础上的继续细化，不再只做统一风格收敛，而是按意图类型给出不同的信息组织结构：
- `TODO`：做成接近参考图 1 的待办列表样式
- `CRM`：做成规则的二维信息表
- `LEDGER`：做成紧凑信息表，金额信息优先

共同目标：
- 总体风格继续保持上一轮已建立的“单卡片、低边界、弱层级”方向
- 每条信息尽量一行显示，减少块状背景和编辑态强调
- 不再通过“可编辑行特殊背景”来提示编辑能力，改为整行点击编辑
- 保留 AI 收件箱原有主要功能和次级折叠区机制

3. **编辑提示还偏显性**
   - 虽然背景已弱化，但目前每行仍保留右侧编辑图标
   - 用户本轮选择了“整行点击编辑”，因此需要进一步去掉显性编辑提示

## 二、方案决策

### 2.1 已确认的展示决策

- `TODO`：待办列表样式，尽量参考图片 1
- `CRM`：表格/二维信息表样式
- `LEDGER`：紧凑信息表样式
- 编辑入口：整行点击编辑，不单独显示待编辑行背景色

### 2.2 本次实现原则

1. **按意图分结构，不按设备分结构**
   - 设备差异只负责响应式
   - 主要结构差异由 `intentTag` 决定

2. **主区强调“阅读结构”，不是“字段控件结构”**
   - TODO 要像列表
   - CRM 要像表格
   - LEDGER 要像账单信息卡

3. **风格继续统一**
   - 三种结构虽然不同，但都必须共享：
     - 弱边线
     - 低背景对比
     - 紧凑间距
     - 同一字体层级
     - 同一底部操作区

4. **不改变业务能力，只换展示壳**
   - 仍使用现有字段编辑回调
   - 仍使用当前次级信息折叠区
   - 不改确认/拒绝/撤销/重新生成逻辑

## 三、拟修改文件与具体方案

### 3.1 `lib/features/idea_stream/presentation/pages/idea_detail_page.dart`

这是本次唯一需要修改的主文件。

#### A. 改造 `_InboxFieldList` 的分发逻辑

**要改什么**
- 从当前“按屏幕切 PC/Mobile 布局”升级为“先按意图切结构，再按屏幕做响应式细化”

**怎么改**
- 在 `_InboxFieldList.build()` 内增加按 `intentTag` 的结构分发，例如：
  - `_buildTodoLayout(...)`
  - `_buildCrmLayout(...)`
  - `_buildLedgerLayout(...)`
- 保留 `LayoutBuilder`，但它只处理列宽和断点，不再决定主要结构类型

**为什么这样改**
- 本轮需求核心不是“再紧凑一点”，而是“不同事项用不同结构”

#### B. TODO：重做为待办列表样式

**目标**
- 接近参考图 1 的“待办列表卡片内容区”
- 每条内容一行显示，不再像字段卡片

**拟采用结构**
- 顶部保留主标题/摘要（由 `_buildDispatchInboxCard()` 继续承担）
- 主字段区改成一组待办式行项目：
  - `title` 作为首条主项，字号稍大
  - `due_date` 若存在，作为带时间图标的次级行
  - `priority / assignee / notes / description` 按内容存在性转成列表项
- 每个条目结构尽量为：
  - 左侧轻图标或圆点/勾选样式占位
  - 右侧单行或单主行 + 单副行文本
- 不给单行额外背景色，不做独立块
- 整行可点击编辑

**注意**
- 这里是“待办列表样式”，不是要真的引入已完成/未完成勾选逻辑
- 可使用参考图的列表感，但不新增真正的 todo 状态机

#### C. CRM：重做为二维信息表

**目标**
- 像一张轻量客户资料表
- 字段更规整，减少当前“多条信息块”感

**拟采用结构**
- 双列表格优先：
  - 左列字段名
  - 右列字段值
- 小屏时：
  - 保持一行一项的“标签-值”横向布局
  - 长文本允许副行换行，但仍保持单项一条记录
- 大屏时：
  - 两列并排信息表，每个单元仍是“字段名 / 值”

**特殊处理**
- `person_name / company / contact / phone / email` 作为高优先字段靠前
- `notes / description / address` 作为长字段排后
- 整项可点击编辑，但不出现独立编辑图标和背景强调

#### D. LEDGER：重做为紧凑信息表

**目标**
- 像简化账单卡
- 金额是最强主信息，其他字段是次级账单信息

**拟采用结构**
- 头部小结：
  - `amount` 突出显示
  - `type` / `ledger_category` 作为次级标签或紧凑副信息
- 下方信息表：
  - `date`
  - `description`
  - `notes`
- 保持紧凑信息表样式，不做大块背景
- 整行可点击编辑

#### E. 弱化 `_InboxFieldChip`

**要改什么**
- 当前 `_InboxFieldChip` 仍是“行块”
- 本轮要把它进一步抽象成“行渲染基元”或只保留为通用信息行

**怎么改**
- 去掉或大幅弱化：
  - 背景色
  - 独立圆角块感
  - 右侧编辑图标
- 保留点击区域，但点击反馈仅靠 `InkWell`
- 如果 TODO/CRM/LEDGER 三类结构差异过大，可减少 `_InboxFieldChip` 的职责：
  - 将其保留给 CRM/LEDGER 使用
  - TODO 改为单独的列表项组件

#### F. 保持 `_buildDispatchInboxCard()` 不做大改，只补齐结构衔接

**要改什么**
- 保持上一轮的头部、次级信息折叠、底部操作区
- 只替换主内容区的具体渲染结构

**怎么改**
- 继续通过 `_buildInboxFields(...)` 进入主内容区
- 但 `_buildInboxFields()` / `_InboxFieldList` 内部按意图选择结构
- 若 TODO 需要更接近参考图，可在 `_buildDispatchInboxCard()` 中为 TODO 增加更接近“列表标题 + 列表项”的主区节奏

## 五、假设与边界

### 5.1 已确认的假设

- “参考图片 1 修改”主要指向 TODO 主内容区的视觉结构，而不是整张卡完全复刻
- `CRM` 和 `LEDGER` 允许使用不同结构，但总风格要与 TODO 卡片一致
- “一条记录一行显示”表示优先做列表/表格中的单项单行表达，不再做块状字段卡
- “不特别显示待编辑行的背景色”意味着可点击，但不通过背景或显性编辑 icon 强调

### 5.2 不在本次计划内

- 不新增真实的待办勾选完成逻辑
- 不改 AI 收件箱状态机与分发逻辑
- 不改次级信息折叠区的业务能力
- 不改单独的数据库 / repository / service
